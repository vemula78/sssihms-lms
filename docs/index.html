Prototype · not connected to hospital systems · no patient data

A learning system built around three kinds of formation, not one.

SSSIHMS LMS is a WordPress plugin for Sri Sathya Sai Institute of Higher Medical Sciences, Whitefield — a charitable tertiary hospital where care is free. It carries clinical competency tracking, allied-health practical evaluation, and chaplaincy formation side by side, on infrastructure the hospital's small IT team already runs.

PHP 8 / WordPress plugin MySQL, 22 tables DPDP Act 2023 NABH audit trail Mobile-first

Why a WordPress plugin

The hospital already operates WordPress and MySQL, and its IT team already maintains a plugin of this shape. Building the LMS the same way means one deployment artifact, one set of skills to keep it running, and no new server to patch — a deliberate trade of architectural purity for a small charitable hospital's actual maintenance capacity. Custom relational tables (not post-meta) keep NABH-grade rosters, transcripts, and compliance exports a straightforward query rather than an EAV puzzle.

How it's assembled

Three tracks, one system

Clinical

Competency & compliance

Skills checklists with preceptor sign-off, clinical-hour and rotation tracking, credential documents (license, BLS/ACLS, immunization) with expiry alerts.

Allied health

Practical evaluation

Discipline-tagged checklists for lab and procedural competencies, evaluator sign-off scoped to assigned learners only, exportable evidence for accreditation.

Chaplaincy

Reflection & mentorship

Reflective journals with per-entry visibility — private, mentor-visible, or instructor-visible — enforced server-side with no administrator override.

Shared core

Courses, quizzes, certificates

Modular course authoring, randomized server-graded quizzes from reusable question banks, auto-issued certificates with public code verification.

Confidentiality & compliance, by construction

Every reflective-journal read path — single entry, list, comment thread, admin counts — passes through one gate function. Private entries are readable by their author only; administrators never get content access, even to mentor- or instructor-visible entries, only aggregate counts (DPDP data minimisation). Credential documents live outside the public uploads path behind an authenticated endpoint. Every compliance-relevant action — enrolments, quiz submissions, sign-offs, hour approvals, document verification, certificate issuance — writes to an append-only audit log with no update or delete path, for NABH review.
